6. Key Design Decisions
===============================================================================

6.1 Why Assignability Rules?
  - Solves the core problem: IsType uses exact type equality
  - Interface types need assignability, not equality
  - Follows Go language specification (reflect.Type.AssignableTo)

6.2 API Design
  - Consistent with IsType: AssignableToTypeOf(example)
  - For interfaces: use (*InterfaceType)(nil) idiom
  - No new reflection boilerplate required for users
  - Panics on misuse with clear error message

6.3 Error Message Improvements
  - Old: "type <nil> != type Context" (unclear)
  - New: "type int not assignable to type context.Context" (clear)
  - New: "<nil> not assignable to type string" (clear)

6.4 Full Integration
  - Works with Mock.On()
  - Works with Arguments.Diff()
  - Works with Arguments.Assert()
  - Works with Mock.AssertCalled()
  - Works with Mock.AssertExpectations()
  - Works with callString() for error reporting
  - Works with Arguments.String() for display
